# DATA_PREPROCESSING

## 1. 프로젝트 개요

본 프로젝트는 판교 제1테크노밸리와 위례 계획구역을 비교하는 도시 데이터 기반 대시보드이다. 분석 탭은 `토지이용`, `개발실현도`, `직주·산업`, `접근성`의 네 영역으로 구성되며, 두 지역의 도시 기능 차이를 지도와 통계 패널로 비교하도록 설계하였다.

핵심 비교 관점은 다음과 같다.

- 판교: 업무·고용·산업 집적 중심 지역
- 위례: 주거 기반 위에 상업·업무 기능이 혼합된 계획도시

구분    |	본 프로젝트 적용 기준
시간범위	|  SGIS 인구·가구·사업체·종사자는 2023년, 용도지역은 토지이음 2024년 1월·2월 갱신본, 건축물대장은 2026년 6월 확보본 중 2023년 12월 31일 이전 건축물 기준
공간범위  |	판교 제1테크노밸리 연구 경계, 위례 업무·상업 기능권 연구 경계
공간단위  |	용도지역 polygon, 필지, 건축물/주소, SGIS 집계구, 네트워크 노드·링크, 등시간권 polygon
시간단위  |	접근성은 0~60분 범위를 10분 단위로 누적 산출, 30분·60분 등시간권을 주요 비교 지표로 사용. 그 외 항목은 시계열 분석이 아니라 기준시점 단면 비교

## 6. 공통 전처리 원칙

- 모든 공간자료는 `EPSG:5186`으로 통일하였다.
- 분석경계 기준으로 `clip` 또는 `intersection`을 수행하였다.
- 면적 계산은 모두 `EPSG:5186` 평면좌표계를 기준으로 수행하였다.
- 중복 polygon은 제거하거나 중복 계산이 발생하지 않도록 처리하였다.
- 결측 구역은 임의 추정하지 않고 `데이터 없음`으로 유지하였다.
- 자료별 source 또는 처리 단계 정보는 산출물 속성 또는 보고서에 기록하였다.
- 최종 대시보드 수치는 동일한 분석경계 기준으로 산출하였다.

## 7. 분석경계 처리

### 7.1 경계 설정 원칙

- 본 연구는 행정구역 경계가 아니라 분석 목적에 맞춘 기능권 경계를 사용하였다.
- 판교는 성남판교지구 전체가 아니라 제1판교테크노밸리의 핵심 업무·연구·도시지원 구역을 대상으로 한다.
- 위례는 위례신도시 전체가 아니라 업무·상업·복합용지 중심의 비교 구역을 대상으로 한다.
- 토지이용, 개발실현도, 직주·산업, 접근성 등 모든 지표는 이 최종 분석경계를 기준으로 계산하였다.

### 7.2 판교 경계 생성

공식적인 제1판교테크노밸리 단일 경계 SHP를 확보하지 못했기 때문에, 기준 이미지와 `가구및획지/the_geom.shp`를 대조하여 분석경계를 정의하였다.

- 기준 이미지: 판교 제1테크노밸리 기준 이미지
- 기준 필지 데이터: `가구및획지/the_geom.shp`
- 주요 검토 컬럼: `zoneName`, `blockName`, `blockType`, `lotName`, `geometry`

판교의 경우 `zoneName`이 `성남판교지구 택지개발사업`인 필지 중, 제1판교테크노밸리 기준 이미지와 일치하는 도시지원시설·업무시설 중심 블록을 후보로 사용하였다. `blockType` 기준으로 `도시지원시설용지`, `업무시설`, `업무시설기타`를 우선 검토하였고, 기준 이미지와 맞지 않는 `일반상업`, `근린상업`, 남서쪽·남쪽 분산 업무 후보는 제외하였다.

이후 후보 필지를 기준으로 외곽을 정리하고, 사용자가 대시보드 기반 편집과 검증을 거쳐 보정한 `pangyo_boundary_user_drawn2_5186.geojson`을 최종 경계로 사용하였다.

### 7.3 위례 경계 생성

공식적인 위례 업무·상업용지 단일 경계 SHP를 확보하지 못했기 때문에, 기준 이미지와 `가구및획지` 필지 데이터를 대조하여 분석경계를 직접 정의하였다.

- 기준 이미지: `위례지도.png`
- 기준 필지 데이터: `가구및획지/the_geom.shp`
- 사용 컬럼: `zoneName`, `blockName`, `blockType`, `lotName`, `geometry`
- CRS: `EPSG:5186`

위례는 위례신도시 전체 외곽이 아니라 업무·상업 기능을 중심으로 비교하기 위해 다음 용도를 1차 후보로 삼았다.

- 업무시설
- 일반상업
- 근린상업
- 도시지원시설용지
- 복합용지

경계 생성 절차는 다음과 같다.

1. `가구및획지/the_geom.shp`에서 위례 택지개발사업 예정지구 관련 필지를 확인하였다.
2. 기준 이미지 `위례지도.png`와 위치를 대조하였다.
3. 업무·상업 관련 `blockType`을 1차 후보로 추출하였다.
4. 비대상 필지(주거, 공원, 학교, 도로, 주차장, 위례 전체 외곽만 넓히는 비업무·비상업 필지)를 제외하였다.
5. 선택 필지를 `dissolve`하였다.
6. 내부 도로·공지·필지 사이 공간을 포함하도록 buffer 및 외곽 정리를 수행하였다.
7. 최종 외곽 polygon을 `wirye_boundary.geojson`으로 저장하였다.

### 7.4 내부 선택 필지와 최종 외곽 경계의 차이

`*_internal_parcels.geojson`은 최종 분석경계가 아니라 경계 생성 근거용 내부 선택 필지이다. 실제 분석에는 `*_boundary.geojson`만 사용하였다.

최종 외곽 경계 면적은 내부 선택 필지 면적보다 크다. 이는 내부 도로, 공지, 필지 사이 공간을 포함하도록 외곽 polygon을 정리했기 때문이다. 따라서 위례 경계와 판교 경계 모두, 단순한 필지 집합이 아니라 기능권 분석을 위한 외곽 연구 경계로 해석해야 한다.

### 7.5 경계 데이터 한계

- 공식 단일 경계 SHP가 없거나 확보되지 않은 경우, 기준 이미지와 필지 데이터를 조합하여 경계를 정의하였다.
- 따라서 본 프로젝트의 경계는 행정적 법정 경계가 아니라 분석 목적에 맞춘 연구 경계이다.
- 판교는 성남판교지구 전체가 아니라 제1판교테크노밸리 핵심 업무·연구 기능권을 대상으로 한다.
- 위례는 위례신도시 전체가 아니라 업무·상업·복합 기능 중심의 비교 구역을 대상으로 한다.

## 11. SGIS 인구·가구·사업체·종사자 데이터 처리

- 출처: SGIS
- 기준시점:
  - 인구·가구: 2023년
  - 사업체·종사자: 2023년
  - 집계구 경계: 2025년 2분기
- 공간 단위: 집계구

### 11.1 왜 SGIS 값이 추정값인가

SGIS 원자료는 집계구 단위 통계이다. 그러나 판교·위례 분석경계는 집계구 경계와 정확히 일치하지 않는다. 따라서 집계구가 분석경계에 일부만 걸치는 경우가 발생한다.

이때 집계구 전체 값을 그대로 넣으면 과대계산되고, 해당 집계구를 제외하면 과소계산된다. 이를 피하기 위해, 집계구와 분석경계가 겹치는 면적 비율을 계산한 뒤 그 비율만큼 인구·가구·사업체·종사자 값을 배분하였다. 이를 `면적비례 배분(area-proportional allocation)`이라고 한다.

예를 들어 한 집계구의 종사자 수가 1,000명이고, 그 집계구 면적의 30%가 판교 분석경계와 겹친다면, 본 분석에서는 해당 집계구 종사자 300명을 판교에 배분하였다.

즉, 대시보드의 인구·가구·사업체·종사자·직주비는 SGIS 원자료를 분석경계에 맞게 면적비례 배분한 값이며, 실제 주소 단위의 정확한 집계값이 아니라 분석경계 기준의 비교 분석용 파생지표이다.

### 11.2 면적비례 배분식

```text
배분값 = 원 집계구 값 × (분석경계와 교차한 면적 / 원 집계구 면적)
```

### 11.3 처리 방식

1. SGIS 집계구 경계와 분석경계를 `intersection`하였다.
2. 원 집계구 전체 면적 대비 교차 면적 비율을 계산하였다.
3. 인구, 가구, 사업체 수, 종사자 수, 산업분류별 종사자 수에 동일한 방식으로 배분값을 계산하였다.

적용 데이터:

- 인구
- 가구
- 사업체 수
- 종사자 수
- 산업분류별 종사자 수

주의:

- 면적비례 배분은 집계구 내부에서 값이 균등하게 분포한다고 가정하는 방식이다.
- 따라서 SGIS 기반 추정 인구, SGIS 기반 추정 종사자, 분석경계 기준 배분값이라는 표현이 더 정확하다.

## 12. 산업구조 및 LQ 산출

- 사용 자료: SGIS 산업분류별 종사자 수
- 처리: 산업별 종사자 수 산출, 산업별 구성비 계산, LQ 산출

LQ 산출식:

```text
LQ = (지역 내 특정 산업 종사자 / 지역 전체 종사자) / (비교권역 내 특정 산업 종사자 / 비교권역 전체 종사자)
```

해석:

- `LQ > 1`: 해당 산업이 상대적으로 특화
- `LQ = 1`: 평균 수준
- `LQ < 1`: 상대적으로 낮은 특화도

산업구성 역시 SGIS 집계구 단위 종사자 수를 분석경계 기준으로 면적비례 배분한 파생지표로 해석해야 한다.

```text
도달 가능 값 = 집계구 값 × (등시간권과 교차한 면적 / 원 집계구 면적)
```

## 18. 지표 산출식

- ### 18.1 LUM

토지이용 혼합도는 Shannon entropy 방식으로 산출하였다.

```text
LUM = -Σ(p_i × ln(p_i)) / ln(n)
```

* `p_i`: i번째 용도 유형의 면적 비율
* `n`: 분석에 포함된 용도 유형 수
* 값이 0에 가까울수록 단일 용도 우세
* 값이 1에 가까울수록 다양한 용도 혼합

본 프로젝트에서는 동일한 공식을 두 기준에 적용하였다.

1. **용도지역 기준 LUM**

   * 입력자료: 토지이음 용도지역 polygon
   * 기준 필드: 용도지역명
   * 산출 방식: 분석경계 안에서 각 용도지역 면적 비율을 계산한 뒤 Shannon entropy 적용

2. **blockType 기준 LUM**

   * 입력자료: 가구 및 획지 polygon
   * 기준 필드: `blockType`
   * 산출 방식: 분석경계 안에서 각 blockType 면적 비율을 계산한 뒤 Shannon entropy 적용

따라서 두 지표는 계산식은 동일하지만, 면적 비율을 산출하는 분류 기준이 다르다. 
용도지역 기준 LUM은 제도상 용도지역의 혼합도를 나타내고, blockType 기준 LUM은 계획 블록 단위의 세부 기능 혼합도를 나타낸다.


### 18.2 coverage

용도지역 자료가 분석경계를 얼마나 덮는지 확인하기 위한 지표이다.

```text
coverage = 용도지역 polygon이 덮는 면적 / 전체 분석경계 면적
```

* 값이 1에 가까울수록 분석경계 대부분이 용도지역 자료로 설명됨
* 본 프로젝트에서는 용도지역 LUM 산출값의 신뢰성을 확인하는 보조 지표로 사용

### 18.3 missing area

용도지역 polygon이 덮지 못한 분석경계 내부 면적이다.

```text
missing area = 전체 분석경계 면적 - 용도지역 polygon이 덮는 면적
```

* 단위: ㎡
* missing area가 클 경우 용도지역 LUM 해석에 주의 필요

### 18.4 업무시설밀도

분석경계 안에 업무시설 연면적이 얼마나 집중되어 있는지를 나타내는 지표이다.

```text
업무시설밀도 = 업무시설 연면적 / 분석면적(ha)
```

* 단위: ㎡/ha
* 값이 클수록 단위면적당 업무공간 집적이 강함

### 18.5 업무시설 연면적비율

전체 건축물 연면적 중 업무시설이 차지하는 비율이다.

```text
업무시설 연면적비율 = 업무시설 연면적 / 전체 건축물 연면적
```

* 값이 클수록 개발된 건축물 중 업무 기능 비중이 높음

### 18.6 직주비

거주 인구 대비 종사자 수를 나타내는 지표이다.

```text
직주비 = 종사자 수 / 거주 인구
```

* 값이 클수록 주거지보다 고용 중심지 성격이 강함
* 거주 인구가 매우 작은 지역에서는 값이 크게 나타날 수 있으므로 해석에 주의 필요

### 18.7 종사자 밀도

분석면적 대비 종사자 수를 나타내는 지표이다.

```text
종사자 밀도 = 종사자 수 / 분석면적(ha)
```

* 단위: 명/ha
* 값이 클수록 고용 집적도가 높음

### 18.8 개발필지비율

전체 필지 중 건축물대장과 결합된 필지의 비율이다.

```text
개발필지비율 = 건축물이 결합된 필지 수 / 전체 필지 수
```

* 건축물대장과 필지가 결합된 경우 해당 필지를 개발필지로 판단
* 주소·지번 결합 기준이므로 일부 오조인 가능성 있음

### 18.9 도달 가능 인구·종사자

등시간권 안에 포함되는 인구와 종사자를 면적비례 방식으로 추정하였다.

```text
도달 가능 값 = 집계구 값 × (등시간권 교차면적 / 집계구 전체면적)
```

* 집계구가 등시간권과 일부만 겹칠 경우, 겹친 면적 비율만큼 인구·종사자를 배분
* 산출값은 실제 통행 인원이 아니라 접근 가능한 인구·종사자 규모의 추정값

## 20. 데이터 한계

1. 데이터 기준시점이 완전히 동일하지 않다.
2. 분석경계는 행정구역 전체 경계가 아니라 기준 이미지와 `가구및획지` 자료를 기반으로 구성한 연구 경계이다.
3. 위례는 위례신도시 전체가 아니라 업무·상업·복합 기능을 중심으로 설정한 분석경계이다.
4. 판교도 성남판교지구 전체가 아니라 제1판교테크노밸리 핵심 업무·연구 구역을 기준으로 설정하였다.
5. 용도지역은 토지이음 2024년 1월/2월 갱신 자료를 조합하였고, 서로 다른 시점 자료를 결합한 한계가 있다.
6. 위례 용도지역에는 소규모 잔여 결측이 존재한다.
7. SGIS 값은 집계구 단위 원자료를 분석경계와 교차한 면적 비율로 배분한 값이므로, 실제 주소 단위 집계값이 아니라 비교 분석용 추정값이다.
8. 접근성의 도달 가능 인구·종사자 역시 SGIS 집계구를 등시간권 polygon에 면적비례 배분한 값이다.
9. 건축물대장과 필지는 주소·지번 기반 key로 결합했으므로 일부 오조인 가능성이 있다.
10. 건축물대장 날짜 필터를 적용했지만, 날짜 결측 건축물에 대한 해석 한계가 남는다.
11. 접근성 분석은 실제 배차, 환승, 보행 접근시간, 혼잡도를 완전히 반영하지 못한다.
12. OSM 도로망은 편집 시점과 정확도 차이가 있을 수 있다.
13. 최종 지표는 행정통계 원자료 자체가 아니라, 동일 분석경계 기준에서 비교 가능하도록 만든 파생지표이다.
