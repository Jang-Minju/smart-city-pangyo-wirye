# 대시보드
# BUILD_SPEC — 판교 vs 위례 도시공간 비교 대시보드

> 이 문서는 AI 코딩 에이전트(Codex, Cursor, Claude Code 등)에게 줄 대시보드 구현 요청서다.
> 미리 만들어 둔 앱은 없으며, 이 스펙을 기준으로 단계별로 구현한다.
> 한 번에 전체를 만들지 않고, 각 단계가 끝날 때마다 실행 확인 후 다음 단계로 넘어간다.

---

## 0. 한 줄 소개

판교 제1테크노밸리와 위례 계획구역을 대상으로 토지이용, 개발실현도, 직주·산업, 접근성을 비교하는 **지도 중심 도시공간 분석 대시보드**.

---

## 1. 프로젝트 목적

이 대시보드는 판교와 위례를 비교하여 다음 질문에 답하는 것을 목표로 한다.

* 판교는 왜 업무·고용 중심지로 기능하는가?
* 위례는 왜 주거 중심성이 강하고 업무·상업 기능 활성도가 낮게 나타나는가?
* 두 지역은 토지이용, 개발실현도, 직주균형, 산업구성, 접근성에서 어떤 차이를 보이는가?

최종 결론은 다음 방향으로 제시한다.

* 판교는 업무시설·종사자·정보통신/전문서비스 중심의 고용 집적지다.
* 위례는 주거·생활서비스 중심성이 강한 신도시형 공간이다.
* 위례는 내부 보행 네트워크는 조밀하지만, 업무·고용 기능으로 이어지는 정도는 약하다.

## 2. 기술 스택 / 제약

### 2-1. 기술 스택

* React + Vite
* deck.gl
* Recharts
* CSS 또는 Tailwind 중 하나 선택
* 정적 웹 대시보드
* GitHub Pages 배포
* 데이터는 `public/data/` 폴더의 GeoJSON, CSV, JSON 파일을 `fetch`해서 사용

### 2-2. 제약

* 백엔드 서버 없음
* 로그인 없음
* 데이터베이스 없음
* 실시간 API 호출 없음
* 사용자 파일 업로드 기능 없음
* AI 채팅 없음
* 모바일 전용 화면 없음
* 기존 분석 결과 재계산 금지
* 기존 `derived_data` 파일 덮어쓰기 금지
* 대시보드용 복사본은 `public/data/`에 별도로 둔다.

### 2-3. 베이스맵

우선 API 키가 필요 없는 배경지도를 사용한다.

추천:

* CartoDB Positron
* OpenStreetMap
* MapLibre 기본 스타일

VWorld는 선택사항이다.
VWorld를 사용할 경우 `.env`에 `VITE_VWORLD_KEY`를 두고, GitHub Pages 배포 시 키 노출과 도메인 제한 문제를 확인한다.

## 3. 전체 화면 구조

전체 앱은 한 페이지 웹 대시보드로 구성한다.

```text
┌─────────────────────────────────────────────────────────────┐
│ 제목 + 핵심 KPI 카드                                         │
├──────────────┬──────────────────────────────┬───────────────┤
│ 왼쪽 메뉴      │            지도 영역           │ 오른쪽 분석 패널 │
│ 탭 메뉴        │          deck.gl map          │ 차트/표/해석     │
│ 레이어 토글    │                              │               │
└──────────────┴──────────────────────────────┴───────────────┘
```

공통 요구사항:

* 데스크톱 브라우저 기준으로 설계한다.
* 지도는 대시보드의 중심 요소다.
* 지도, 차트, 해석문이 한 화면에서 같이 보여야 한다.
* 과도한 스크롤을 만들지 않는다.
* 도시공간 분석용 admin dashboard 스타일로 구성한다.

## 4. 종합 화면 구조

종합 화면은 판교와 위례를 직접 비교할 수 있도록 좌우 2분할 지도로 구성한다.

```text
┌─────────────────────────────────────────────────────────────┐
│ 판교 제1테크노밸리 vs 위례 계획구역 도시공간 비교 대시보드        │
│ [직주비] [업무시설밀도] [업무시설비율] [종사자수] [접근성]        │
├──────────────────────────────┬──────────────────────────────┤
│ 판교 지도                     │ 위례 지도                     │
│ deck.gl map                   │ deck.gl map                   │
│ [판교 요약 카드 overlay]        │ [위례 요약 카드 overlay]        │
├──────────────────────────────┴──────────────────────────────┤
│ 핵심 결론: 판교는 업무·고용 중심, 위례는 주거 중심 성격이 강함     │
└─────────────────────────────────────────────────────────────┘
```

### 종합 화면 요구사항

* 판교와 위례 지도를 좌우로 나란히 표시한다.
* 두 지도는 같은 레이어 모드를 공유한다.
* 예: “종사자밀도” 선택 시 판교와 위례 모두 종사자밀도 레이어를 표시한다.
* 각 지도 위에는 반투명 요약 카드를 overlay로 표시한다.
* 상단 KPI 카드는 두 지역의 핵심 지표를 직접 비교한다.
* 하단에는 한 줄 결론을 표시한다.
* 지도 영역을 좁히는 큰 사이드바는 종합 화면에서는 사용하지 않는다.

## 5. 세부 분석 탭 구조

세부 분석 탭에서는 큰 지도 1개를 중심으로 사용한다.

```text
┌──────────────┬──────────────────────────────┬───────────────┐
│ 탭/레이어     │          큰 지도 영역           │ 분석 패널       │
│              │ [판교 보기] [위례 보기] [비교]   │ 그래프          │
│              │                              │ 지표표          │
│              │                              │ 해석문          │
└──────────────┴──────────────────────────────┴───────────────┘
```

### 세부 분석 탭 공통 요구사항

* 지도는 deck.gl로 구현한다.
* 판교 보기 / 위례 보기 / 비교 보기 버튼을 둔다.
* 좌측에는 탭 메뉴와 레이어 토글을 둔다.
* 우측에는 해당 탭의 차트, 지표표, 해석문을 표시한다.
* 비교 보기에서는 판교와 위례의 분석경계를 함께 보여주거나, 필요 시 split map 형태로 보여준다.
* 같은 지표는 판교와 위례에 동일한 색상 범례를 적용한다.

## 8. 주요 지표

대시보드에서 반드시 표시할 핵심 지표는 다음과 같다.

### 8-1. 종합 KPI

| 지표          |          판교 |          위례 | 해석                   |
| ----------- | ----------: | ----------: | -------------------- |
| 직주비         |      110.96 |       0.214 | 판교는 고용 중심, 위례는 주거 중심 |
| 업무시설밀도      |  24,517㎡/ha |   4,215㎡/ha | 판교가 약 5.8배 높음        |
| 업무시설 연면적 비율 |       73.6% |       18.3% | 판교의 업무기능 집중          |
| 종사자수        |   약 61,849명 |   약 25,567명 | 판교의 고용 규모 우세         |
| OSM 도로밀도    | 21.90km/km² | 33.80km/km² | 위례 내부 보행 네트워크가 더 조밀  |

주의:

* OSM 도로밀도는 보행 네트워크 보조지표다.
* 도로밀도가 높다고 업무지구 활성도가 높다는 뜻은 아니다.
* 위례의 OSM 도로밀도는 생활가로, 보행로, 산책로, 단지 내부길 등이 포함된 결과로 해석한다.

## 10. 탭별 요구사항

### 10-1. 종합 탭

지도:

* 판교/위례 split map
* 분석경계
* 핵심역
* 주요 지표 overlay

차트/표:

* 상단 KPI 카드
* 판교 vs 위례 요약 비교표
* 하단 결론 문장

완료 기준:

* 판교와 위례 지도가 나란히 표시된다.
* 각 지도 위에 요약 카드가 표시된다.
* KPI 카드가 실제 데이터 기준으로 표시된다.
* 지도와 카드가 겹쳐도 가독성이 유지된다.

---

### 10-2. 토지이용 탭

지도:

* 용도지역 레이어
* blockType 레이어

차트:

* LUM 비교
* 용도지역 구성비
* blockType 구성비

해석:

* 위례의 LUM이 높게 나와도 업무기능 활성도가 높다는 뜻은 아니다.
* 위례는 계획구역 전체의 주거·녹지·상업 혼합성이 반영된 결과다.

완료 기준:

* 판교/위례 용도지역이 동일한 색상 기준으로 표시된다.
* LUM 수치가 카드 또는 차트로 표시된다.
* 용도별 구성비 차트가 표시된다.

---

### 10-3. 개발실현도 탭

지도:

* 건축물/필지 레이어
* 업무시설 강조 레이어
* 미건축/공지 추정 필지 표시 가능하면 표시

차트:

* 업무시설 연면적 비율
* 업무시설밀도
* 개발필지비율
* 미건축/공지 추정비율
* FAR/BCR 보조지표

해석:

* 판교는 업무시설 비율과 업무시설밀도가 높다.
* 위례는 개발필지비율이 낮고 업무시설 비중이 낮다.
* 미건축/공지 비율은 추정값으로 표시한다.

완료 기준:

* 업무시설 관련 지표가 판교/위례 비교 형태로 표시된다.
* 추정값에는 “추정” 또는 “estimated” 표시가 붙는다.

---

### 10-4. 직주·산업 탭

지도:

* SGIS 인구밀도
* SGIS 종사자밀도
* 사업체밀도

차트:

* 직주비 비교
* 인구/가구/사업체/종사자 비교
* 산업구성
* LQ 상위 산업

해석:

* 판교는 정보통신업, 전문·과학·기술서비스 중심이다.
* 위례는 교육, 보건·사회복지, 생활서비스 성격이 강하다.
* LQ는 “두 사례지역 간 상대 산업특화도”로 해석한다.

완료 기준:

* 인구밀도와 종사자밀도는 같은 범례 기준으로 표시된다.
* 직주비가 KPI로 명확히 표시된다.
* LQ는 “상대 산업특화도”라고 표기된다.

---

### 10-5. 접근성 탭

지도:

* 핵심역
* 500m/1km 역세권 buffer
* 30분/60분 등시간권
* OSM 도로망

차트:

* 30분 도달 인구
* 30분 도달 종사자수
* 60분 도달 인구
* 60분 도달 종사자수
* 누적 접근성 곡선
* 도로밀도 비교

해석:

* 지하철 접근성은 네트워크 기반 근사값이다.
* 60분 등시간권은 광역적으로 넓어질 수 있으므로 절대값 해석에 주의한다.
* OSM 도로밀도는 보행 네트워크 보조지표다.

완료 기준:

* 핵심역과 buffer, isochrone이 지도에 표시된다.
* OSM 도로망은 얇은 선으로 표시된다.
* 접근성 수치와 도로밀도 수치가 구분되어 표시된다.

---

### 10-6. 결론 탭

지도:

* 필요 시 판교/위례 경계만 표시

표/해석:

* 최종 비교표
* 핵심 결론 3개
* 한계점
* 정책적 시사점

핵심 결론:

1. 판교는 업무시설·종사자·정보통신/전문서비스 산업이 집중된 고용 중심지다.
2. 위례는 주거와 생활서비스 중심성이 강하며, 업무·상업 기능의 실현 정도가 상대적으로 낮다.
3. 위례는 내부 보행 네트워크는 조밀하지만, 이것이 고용 중심 업무기능으로 이어지지는 않는다.

완료 기준:

* 지표와 결론이 서로 충돌하지 않는다.
* 한계점이 명시된다.
* 교수자가 봤을 때 분석 흐름이 한눈에 보인다.

## 11. 디자인 규칙

* 도시공간 분석용 admin dashboard 스타일

## 12. 단계적 빌드 계획

한 번에 전체를 만들지 않는다.
총 7단계로 나누어 구현한다.

---

### 1단계. 데이터 준비

작업:

* `derived_data` 폴더를 검사한다.
* 대시보드에 필요한 GeoJSON/CSV/JSON 파일 목록을 작성한다.
* 존재하는 파일과 없는 파일을 구분한다.
* 대시보드에서 사용할 파일만 `public/data/`로 복사한다.
* 파일명이 너무 길면 간단한 이름으로 바꾼다.
* 원본 `derived_data`는 수정하지 않는다.

출력:

* `public/data/`
* `dashboard/public_data_manifest.md`

완료 기준:

* 필요한 데이터 목록이 표로 정리된다.
* 모든 대시보드용 데이터가 `public/data/`에 있다.
* 각 파일의 출처가 manifest에 기록된다.
* 없는 파일은 mock data를 만들지 않고 “없음”으로 표시된다.

---

### 2단계. React 기본 앱 + 레이아웃

작업:

* Vite + React 프로젝트를 생성한다.
* 기본 CSS를 설정한다.
* 상단 헤더를 만든다.
* KPI 카드 영역을 만든다.
* 왼쪽 탭 메뉴를 만든다.
* 중앙 지도 placeholder를 만든다.
* 오른쪽 분석 패널 placeholder를 만든다.
* 종합 / 토지이용 / 개발실현도 / 직주·산업 / 접근성 / 결론 탭을 만든다.

완료 기준:

* `npm install` 성공
* `npm run dev` 성공
* 브라우저에서 기본 화면이 열린다.
* 탭 UI가 보인다.
* 콘솔 에러가 없다.
* 아직 지도와 데이터가 없어도 된다.

---

### 3단계. deck.gl 지도 구현

작업:

* deck.gl 지도 컴포넌트를 만든다.
* 베이스맵을 표시한다.
* 판교 보기 / 위례 보기 / 비교 보기 버튼을 만든다.
* 종합 화면에서 판교 지도와 위례 지도를 좌우 2분할로 표시한다.
* 각 지도 위에 요약 카드 overlay를 배치할 수 있는 구조를 만든다.

완료 기준:

* 지도 화면이 뜬다.
* 판교 보기 클릭 시 판교 중심으로 이동한다.
* 위례 보기 클릭 시 위례 중심으로 이동한다.
* 비교 보기 클릭 시 판교/위례를 함께 볼 수 있다.
* 종합 화면에서 좌우 split map 구조가 보인다.
* 콘솔 에러가 없다.

---

### 4단계. 지도 레이어 연결

작업:

* 분석경계 레이어 연결
* 용도지역 레이어 연결
* blockType 레이어 연결
* SGIS 집계구 레이어 연결
* 건축물/필지 레이어 연결
* 핵심역 레이어 연결
* 역세권 buffer 레이어 연결
* 등시간권 레이어 연결
* OSM 도로망 레이어 연결
* 레이어 토글 구현
* 지도 범례 구현
* 기본 hover tooltip 구현

완료 기준:

* 각 레이어가 탭별로 표시된다.
* 레이어 토글이 작동한다.
* 분석경계가 정확히 보인다.
* OSM 도로망은 얇은 선으로 표시된다.
* tooltip에 최소한 지역명, 레이어명, 주요 속성이 표시된다.
* 콘솔 에러가 없다.

---

### 5단계. KPI 카드 + 차트 연결

작업:

* `dashboard_indicators.json` 또는 관련 CSV/JSON 파일을 읽는다.
* KPI 카드에 실제 수치를 연결한다.
* Recharts 그래프를 구현한다.

필수 KPI:

* 직주비
* 업무시설밀도
* 업무시설 연면적 비율
* 종사자수
* 접근성 지표
* OSM 도로밀도

필수 차트:

* LUM 비교
* 용도지역 구성비
* blockType 구성비
* 업무시설밀도 비교
* 업무시설 연면적 비율 비교
* 개발필지비율 비교
* 직주비 비교
* 산업구성
* LQ 상위 산업
* 도달 인구/종사자 비교
* 누적 접근성 곡선
* 도로밀도 비교

완료 기준:

* KPI 카드에 실제 수치가 표시된다.
* 숫자 단위가 표시된다.
* 각 탭에 필요한 그래프가 표시된다.
* 그래프 제목과 단위가 표시된다.
* 판교와 위례 색상이 일관되게 유지된다.

---

### 6단계. 해석문 + 결론 탭 구성

작업:

* 각 탭의 분석 해석문을 카드로 표시한다.
* 결론 탭에 최종 비교표를 넣는다.
* 핵심 결론 3개를 표시한다.
* 한계점을 표시한다.
* 정책적 시사점을 표시한다.

탭별 해석 핵심:

* 토지이용: 위례 LUM이 높아도 업무기능 활성도가 높다는 의미는 아니다.
* 개발실현도: 판교는 업무시설 비율과 업무시설밀도가 높다.
* 직주·산업: 판교는 정보통신/전문서비스 중심, 위례는 생활서비스 중심이다.
* 접근성: 지하철 등시간권은 네트워크 기반 근사값이며, OSM 도로밀도는 보행 네트워크 보조지표다.
* 결론: 판교는 고용·업무 중심지, 위례는 주거·생활서비스 중심성이 강한 공간이다.

완료 기준:

* 각 탭에 분석 결과를 설명하는 문장이 있다.
* 결론 탭만 봐도 분석 요지가 이해된다.
* 지표와 결론이 서로 충돌하지 않는다.
* 한계점이 명시된다.

---

### 7단계. 스타일 정리 + 배포

작업:

* 색상 통일
* 카드 간격 정리
* 지도 overlay 가독성 개선
* 범례 디자인 정리
* tooltip 디자인 정리
* 일반 노트북 화면에서 깨지지 않도록 최소 반응형 정리
* Vite base 경로 설정
* GitHub Pages 배포 설정
* 최종 점검 체크리스트 작성

출력:

* `dashboard/final_checklist.md`

완료 기준:

* `npm run build` 성공
* GitHub Pages에서 페이지가 열린다.
* 배포된 페이지에서 지도와 데이터가 정상적으로 로드된다.
* 콘솔 에러가 없다.
* 모든 탭이 정상 작동한다.
* 모든 주요 데이터가 로드된다.
* 지도 레이어 토글이 정상 작동한다.
* KPI 수치가 분석 보고서와 일치한다.
* 동일 지표의 색상 범례가 판교/위례에 동일하게 적용된다.
* 발표 화면으로 보여도 어색하지 않다.
